# 17. คำถามที่พบบ่อย (Frequently Asked Questions - FAQ)

เอกสารนี้รวบรวมคำถามและคำตอบที่พบบ่อยเกี่ยวกับการติดตั้ง การตั้งค่า การบินสำรวจโดรน การคำนวณงานดินเชิงวิศวกรรม และการทำงานของระบบ GeoMonitor 3D

---

### Q1: ระบบ GeoMonitor 3D สามารถติดตั้งและใช้งานบนเครือข่ายปิด (Air-Gapped Network) ที่ไม่ต่ออินเทอร์เน็ตได้หรือไม่?
**ตอบ:** **ได้ 100%**
ระบบถูกออกแบบมาสำหรับสภาพแวดล้อม On-premises โดยเฉพาะ บริการทั้งหมด (PostgreSQL, PostGIS, Redis, MinIO, Node.js API, Next.js Web) รันอยู่ภายในเครื่องแม่ข่ายองค์กร สำหรับแผนที่ CesiumJS หากไม่มีการเชื่อมต่อไปยัง Cesium Ion ทางอินเทอร์เน็ต ระบบจะสลับไปใช้ Base Tile Imagery ภายในเครื่อง (Local Fallback) หรือสามารถเชื่อมต่อไปยัง Local Tile Server (เช่น GeoServer หรือ TileServer GL) ที่ตั้งอยู่บนเครือข่ายภายในได้

---

### Q2: ระบบรองรับโดรนสำรวจและเซ็นเซอร์กล้องรุ่นใดบ้าง?
**ตอบ:** ระบบรองรับภาพถ่ายจากโดรนสำรวจทุกยี่ห้อที่มีการบันทึกค่าพิกัดภูมิศาสตร์ (EXIF GPS Tags) ในไฟล์ภาพ JPEG/TIFF เช่น:
- **DJI**: Phantom 4 RTK, Mavic 3 Enterprise (M3E), Matrice 300/350 RTK ติดกล้อง Zenmuse P1 หรือ H20
- **Autel**: EVO II Pro Enterprise, EVO Max 4T
- **Fixed-Wing**: senseFly eBee X, WingtraOne GEN II
- **กล้องสำรวจอื่น ๆ**: กล้อง Full-frame (Sony Alpha, Hasselblad) ที่มีการต่อพ่วงระบบ GNSS Logger

---

### Q3: ระบบรองรับภาพถ่ายปริมาณเท่าใด และขนาดพื้นที่สำรวจสูงสุดเท่าใด?
**ตอบ:** 
- ในส่วนของการจัดเก็บภาพถ่ายดิบ (Raw Images) และไฟล์ผลผลิต (Orthomosaic, DSM) บน MinIO ไม่มีข้อจำกัดเรื่องขนาดไฟล์ (รองรับ Multi-Terabyte ตามขนาดดิสก์จริงของเครื่องแม่ข่าย)
- สำหรับการประมวลผล Photogrammetry ต่อหนึ่งภารกิจ แนะนำขนาดพื้นที่ 100 - 3,000 ไร่ (ประมาณ 300 - 2,500 ภาพ) ต่อรอบการประมวลผล เพื่อให้ใช้เวลาและทรัพยากร RAM ของเซิร์ฟเวอร์อย่างเหมาะสม หากพื้นที่ใหญ่กว่านั้น แนะนำให้แบ่งภารกิจการบินเป็นบล็อกย่อย (Sub-blocks)

---

### Q4: ปริมาตรงานดิน (Cut / Fill Volume) ที่คำนวณได้มีความแม่นยำเพียงใด และมีปัจจัยอะไรที่มีผลกระทบ?
**ตอบ:**
ความแม่นยำขึ้นอยู่กับ 3 ปัจจัยหลัก:
1. **การควบคุมพิกัดภาคพื้นดิน (GCP)**: หากใช้โดรน RTK ร่วมกับหมุด GCP อย่างน้อย 5 จุด จะได้ความคลาดเคลื่อนทางดิ่ง (Vertical RMSE) ภายใน **$\pm 3 - 5\text{ cm}$** ทำให้ปริมาตรดินขุดถมมีความแม่นยำสูงระดับงานตรวจรับวิศวกรรม
2. **ความละเอียดเชิงพื้นที่ (GSD)**: ยิ่งบินต่ำ ค่า GSD ยิ่งละเอียด (แนะนำ GSD $\le 3\text{ cm/pixel}$)
3. **การคัดกรองพืชพันธุ์**: พื้นที่ป่าทึบหรือหญ้าสูงจะทำให้ความสูง DSM สูงกว่าระดับผิวดินจริง ควรใช้ DTM (Digital Terrain Model) ในการคำนวณ หรือปรับค่า Threshold การตัดสัญญาณรบกวน ($\epsilon$)

---

### Q5: การประมวลผล Photogrammetry ใช้เวลาเฉลี่ยเท่าใด?
**ตอบ:**
เวลาในการประมวลผลขึ้นอยู่กับจำนวนภาพและสเปกของฮาร์ดแวร์:
- **ภาพ 300 ภาพ (พื้นที่ประมาณ 100 ไร่)**: ใช้เวลาประมาณ 25 - 45 นาที บน CPU 16 Cores / RAM 32 GB
- **ภาพ 1,000 ภาพ (พื้นที่ประมาณ 500 ไร่)**: ใช้เวลาประมาณ 1.5 - 3 ชั่วโมง
- หากมีการ์ดจอ NVIDIA GPU ที่รองรับ CUDA จะช่วยลดระยะเวลาขั้นตอนสกัดจุดรวมภาพ (Feature Matching) ลงได้ถึง 40-60%

### Q6: ระบบอ้างอิงพิกัด (CRS) ที่แนะนำสำหรับการใช้งานในประเทศไทยคืออะไร?
**ตอบ:**
- **EPSG:4326 (WGS 84)**: พิกัดภูมิศาสตร์ (Latitude, Longitude) หน่วยเป็นองศา ใช้สำหรับการจัดเก็บรูปแปลงและแสดงผลบนลูกโลก CesiumJS
- **EPSG:32647 (WGS 84 / UTM Zone 47N)**: พิกัดกริดระนาบ ครอบคลุมพื้นที่ภาคเหนือ ภาคกลาง ภาคใต้ฝั่งตะวันตก และภาคตะวันออกของไทย
- **EPSG:32648 (WGS 84 / UTM Zone 48N)**: ครอบคลุมภาคตะวันออกเฉียงเหนือและภาคใต้ฝั่งตะวันออกบางส่วน
*หมายเหตุ: สำหรับการคำนวณพื้นที่และปริมาตร ระบบจะแปลงเข้าสู่ UTM Zone 47N โดยอัตโนมัติเพื่อให้ได้หน่วยเมตริกที่ถูกต้องทางวิศวกรรม*

### Q7: ทำไมเปิดไฟล์ CSV รายงานใน Microsoft Excel บน Windows แล้วภาษาไทยกลายเป็นภาษาต่างดาว?
**ตอบ:**
ระบบ GeoMonitor 3D ได้ฝังรหัส **UTF-8 BOM (`\uFEFF`)** ไว้ที่จุดเริ่มต้นของไฟล์ CSV ทุกไฟล์ ทำให้ Excel เวอร์ชัน 2016 ขึ้นไปสามารถเปิดอ่านภาษาไทยได้ทันที อย่างไรก็ตาม หากเครื่องผู้ใช้ใช้ Excel รุ่นเก่า ให้แก้ไขดังนี้:
1. เปิดโปรแกรม Excel แล้วเลือกแท็บ **Data (ข้อมูล)** -> **From Text/CSV (จากข้อความ/CSV)**
2. เลือกไฟล์ที่ดาวน์โหลดมา
3. ในช่อง **File Origin (ต้นทางของไฟล์)** ให้เลือกเป็น **65001 : Unicode (UTF-8)** แล้วกด Load

### Q8: สามารถนำผลผลิต Orthomosaic หรือ DSM ไปใช้งานต่อในโปรแกรม GIS อื่นได้หรือไม่?
**ตอบ:** **ได้ทันที**
ไฟล์ผลผลิตทั้งหมดจัดเก็บในรูปแบบมาตรฐานสากล:
- ภาพถ่ายดัดแก้: **Cloud Optimized GeoTIFF (COG)** รองรับ QGIS, ArcGIS Pro, AutoCAD Civil 3D
- แบบจำลองความสูง: **GeoTIFF (Float32)**
- กลุ่มหมอกจุด 3 มิติ: **LAS / LAZ / 3D Tiles**
- รูปแปลงความเปลี่ยนแปลง: **GeoJSON / Shapefile**

### Q9: การเชื่อมต่อระบบเข้ากับ WebODM หรือ NodeODM ภายนอกทำอย่างไร?
**ตอบ:**
ในเวอร์ชันปัจจุบัน Background Worker (`apps/worker/src/index.ts`) มี Pipeline สำหรับจัดทำ Tile และคำนวณสถิติพร้อมใช้งาน หากต้องการผูกการประมวลผลภาพดิบเข้ากับ NodeODM ภายนอก ให้ตั้งค่า URL ใน `.env` ของ Worker เช่น `NODEODM_HOST=http://192.168.1.50:3000` โดยจะมีคู่มือการตั้งค่าสถาปัตยกรรมเพิ่มเติมใน [IMPLEMENTATION-STATUS.md](file:///Users/cangsalak/project/maparmy/docs/user-guide/IMPLEMENTATION-STATUS.md)

### Q10: หากต้องการเปลี่ยนพอร์ตของ Web Frontend จาก 3000 เป็นพอร์ตอื่นต้องทำอย่างไร?
**ตอบ:**
1. แก้ไขไฟล์ `docker-compose.yml` ในส่วนของ Service `geomonitor-web`:
   ```yaml
   ports:
     - "8080:3000"  # เปลี่ยนฝั่งเครื่อง Host เป็นพอร์ตที่ต้องการ เช่น 8080
   ```
2. แก้ไขค่า `CORS_ORIGIN` ในไฟล์ `.env` ของ API ให้ตรงกับพอร์ตใหม่:
   ```env
   CORS_ORIGIN=http://localhost:8080
   ```
3. สั่งรันคอนเทนเนอร์ใหม่ด้วยคำสั่ง:
   ```bash
   docker compose up -d geomonitor-web geomonitor-api
   ```
